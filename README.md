# 时点 · A股回测实验室
独立本地部署的 A 股研究平台（Node.js + SQLite，无需 Sites、D1、R2 或 Cloudflare 账号），支持公开数据采集、按交易日推进、规则基线、财报/新闻时点快照、模拟成交、保存恢复和 JSON 导出。不是券商工具，不会提交真实订单。

## 当前可用

- 沪深北全市场证券目录：巨潮2026-10-08快照5,920个去重条目（上海2,467、深圳3,100、北京353），代码/名称/拼音/旧代码搜索，交易所和板块过滤；包含历史/退市条目，不是存续股票计数
- 10只和120个自然日仅为软建议，不阻止更大范围；输入旁提醒采集时间/存储及AI token成本。规则基线不调用模型，API token为0。目录24小时缓存，刷新失败保留明确标注的旧快照；行情/文档仅为所选股票加载，逐股报告不可用
- 沪深使用腾讯未复权OHLC；北交所使用搜狐公开日线（单次少于100条，代码切换前不自动回填），排除今日报价元数据
- 巨潮资讯公告索引/PDF 来源链接；日期精度不明时，次日才释放
- 每经公开公司新闻搜索，按月后台补充，保留分页覆盖与失败记录；严格标注非完整新闻档案（旧东方财富接口暂不可用）
- 页面可提取巨潮公告 PDF 文本（需 pdftotext，Docker 已包含）；逐条标注正文是否已提取及版本时间；也支持 JSON 导入文本
- 固定等权调仓或买入持有，初始资金、间隔、佣金/税费/滑点可配置
- 当日收盘信号、下一交易日开盘成交；按板块最低申报/递增股数、T+1、保守涨跌停/停牌处理
- SQLite 本地持久化；版本条件更新防止重复推进；来源/快照/决策/费用可导出
- 模型 API 适配器优先从服务端环境读取密钥；可由用户亲自提交一次会话密钥，规则见下文；无密钥时不调用、不用虚构 AI 输出替代

## 重要限制

这是研究原型，不应把结果当作可交易业绩。样本由用户选定，存在选择/幸存者偏差。

1. 未复权行情不是完整含红利总收益。只有明确录入并核验的现金分红会记账；股票分拆、送转、配股、退市、历史 ST 状态等未完整覆盖。异常开盘跳变会暂停，但小幅漏记分红无法靠阈值发现。
2. 新回测采用严格逐日规则：普通主板10%、ST在2026-07-06前5%/之后10%；科创板20%，创业板自2020-08-24起20%，北交所30%。IPO、重新上市、退市整理等特殊日尚不模拟，须提供期间普通交易证据；缺失即暂停而不是猜测10%。科创板最低200股/1股递增，北交所最低100股/1股递增，主板与创业板100股整手。涨跌停开盘保守不成交。老版本已保存run保持旧假设，不自动改写历史结果。
3. 费率在整个回测窗口不变，用户应按历史日期/券商核实。个人红利差别税未计算，已核验现金分红按税前计入。
4. 公告每批最多翻5页（每页30条），未遍历的后续页明确标记；公司财经新闻自动接入每经公开搜索，可按月后台补充。空结果不等于没有消息。新闻索引/摘要可能事后修订，没有不可变历史档案保证。
5. 财报正文仅在成功提取并导入时可用。`pdftotext` 不等于财务表格结构化分析；页面保留来源和解析状态。
6. 限制模型输入截止时间不能删除预训练模型已经记住的未来事实。模型之间应使用相同数据和设置，结果不证明投资能力。
7. 回测连续推进仍由打开的页面发起；数据采集和按月新闻补充支持显式启动的服务端后台任务，关闭页面继续，游标与结果存入SQLite，可暂停和恢复。

## 开发与测试

需要 Node.js 24（本地 SQLite 测试）、npm。安装并运行：

    npm ci
    npm run build
    npm test
    npm run validate
    npm start

本地页面在 http://127.0.0.1:4317 。独立服务器默认仅绑定 loopback，并校验 Host、Origin 和跨站请求；它没有用户账户鉴权，不要直接暴露公网。本地测试中的合成数据仅为标注的单元测试夹具，不随生产数据集发布。

源文件：`worker/engine.js` 会计引擎、`collector.js` 公开采集器、`model.js` 模型适配器、`server.js` API、`page.html` 中文界面。构建脚本产生 `dist/server/index.js`。

## 数据导入格式

顶层包含 `schemaVersion:2,start,end,stocks,documents,sources,coverage,warnings,corporateActions`。当前导入均升级为schemaVersion2，不影响已保存run。
`stocks`: `{code,name,symbol,bars:[{date,open,high,low,close,volume}],ruleEvidence:[]}`，日期升序且不重复。
每只股票的 `ruleEvidence` 格式：`[{start:"2026-09-01",end:"2026-09-30",ordinaryTrading:true,st:false,sourceUrl:"https://可信来源/记录"}]`。这只是格式示例，不能当作真实证据。由导入者核验该期间非IPO/重新上市/退市整理等特殊期、历史ST状态以及除权参考价；平台不验证来源内容。日期未覆盖则暂停该日；仍可浏览原始数据。当前名称/ST快照、上市日期未知均不会自动成为历史规则证据。普通规则最大单笔股数受限，但并非完整撮合引擎。
`documents`: `{id,code,title,publicationDate,availableAt,url,textStatus,kind,text?}`；`availableAt` 必须是带明确时区的时间，且不能早于实际公开时间；日期型公告保守推迟至次日。新闻时区来自来源格式，假设上海时间。
`sources`: 至少记录 HTTPS 来源地址、抓取时间、原始响应 SHA-256、字段和覆盖说明。
`corporateActions`: 目前仅 `{code,recordDate,exDate,payDate,cashPerShare,sourceUrl,taxAssumption:'gross'}` 的已核验现金分红；登记日必须早于除息日，不能重复。

`tools/collector.py` 是有缓存、节流、大小/窗口限制的公开数据采集示例；运行时自行抓取，不随源码发布第三方财报/新闻正文。遵守来源条款、robots 和访问限制，不进行验证码绕过、代理轮换或登录绕过。HTTP 可访问不代表开放再分发许可。

## 模型与安全

模型配置保存提供方、模型标识、预算上限及核实的输入/输出单价。持久密钥只能由用户亲自在本地受保护的 `.env` 或进程环境变量中配置；会话密钥仅能由用户亲自在专用 password 输入框提交，不能填在聊天、代码或数据库。

固定允许的服务端域名，JSON 输出经权重/股票池/证据 ID 验证后才能成为下一交易日的信号。AI 输出每股相对配置分数和总投入比例，由平台按比例计算仓位；保留原始分数、冻结持仓和分配结果，避免多股票加总超过100%。模型只得到截止时点的近期价格和文档片段。资料中的指令视作不可信数据。

每个 run/version 只有一个持久化请求槽位；并发请求不会重复调用。超时/不明结果会停止，不盲目重试。缺失 usage 时费用记为未知。按保守 token 上限预留预算，但实际提供方计费须以账单为准。不以固定100次调用数替代用户预算；预算不足时仍在发请求前停止。保存配置不代表真实 API 已验证，本项目测试未使用收费模型。

## 独立部署（默认方式）

### Docker Compose 一键启动

需要 Docker Engine / Docker Desktop 与 Compose v2，在仓库目录运行：

    docker compose up -d --build

打开 http://127.0.0.1:4317 ，检查 `docker compose ps` 和 `docker compose logs --tail=30`。
容器内绑定 0.0.0.0，但 Compose **只发布到宿主机 127.0.0.1**；不要改为公网地址。
镜像使用 Node 24、非 root 用户，无第三方运行时 npm 依赖。数据库位于命名卷 `ashare-data`；`docker compose down` 保留数据，`docker compose down -v` 会删除卷及数据，勿误用。
Docker 镜像已实际构建并以非 root 用户启动，SQLite 健康接口已验证；npm 路径也已实际启动验证。

### 无 Docker：Node.js 24 / npm

    npm ci
    npm run build
    npm start

也可直接 `node scripts/bundle.mjs && node runtime/server.mjs`，不安装开发依赖即可运行。
默认地址 http://127.0.0.1:4317 。`PORT` 可自定；`DATA_DIR` 指定持久化目录，默认仓库 `.data/ashare.sqlite`；迁移由启动时事务自动执行。Node 的 SQLite 在部分 24.x 版本可能显示实验性提示。
`npm start` 会读取已有 `.env`。需要持久模型密钥时，由用户亲自复制 `.env.example` 为 `.env`、填写并限制文件权限（Unix 下 `chmod 600 .env`）；不要提交或发送该文件。也可只用页面的硅基流动会话 password 输入框。Compose 默认不注入密钥；如确需持久模型密钥，用户自行在 Compose 的 `env_file` 中引用私有 `.env`，不得上传该文件。

### 运行、安全与备份

- `GET /healthz` 是 SQLite 健康检查；`GET /api/status` 显示 `standalone-node` / `SQLite`
- Node 入口拒绝非 loopback 绑定；`ALLOW_CONTAINER_BIND=1` 只为容器内部绑定准备，不能视为鉴权。只信任本机 `127.0.0.1`、`localhost`、`[::1]` 的对应端口 Host
- 请求体上限 1,500,000 字节；需要更大数据集时使用分批采集，不将软股票/日期建议改成硬限制
- 页面刷新或进程重启后可从历史记录恢复数据集与回测；自动推进由页面驱动，关闭页面后不会继续新步骤
- 备份前先停止服务，再备份整个 `.data` 目录或 Docker 数据卷；SQLite WAL/SHM 文件也属于运行中数据库。恢复时停止服务并恢复整个备份，不混入不同时间点文件
- `SIGTERM` / `Ctrl+C` 等待请求收尾并关闭数据库；强制退出可能中断当前网络请求，已提交事务仍在。采集租约过期后可继续；不确定的模型调用不会自动重试，防止重复计费
- 此服务没有登录系统，不支持直接公网多用户部署。本机 loopback 地址仅对运行进程所在电脑可见；助手云端的 loopback 不是用户电脑地址，当前未提供可公开访问 URL，也不承诺永久免费或 24×7 托管
- 发布源码时排除 `.data`、`.env*`（保留空模板）、下载缓存、数据库、新闻全文、用户附件和凭据。JSON 回测导出含用户数据，只用于私人研究，不要推到公共仓库

本分支以独立 Node 服务为主；旧版 Sites 部署另存历史分支。`worker` 文件夹名称仅表示可复用 Fetch API 业务模块，不意味着运行依赖云服务。证券代码目录只包含公开事实与来源说明，不表示其他源站数据允许再分发。

## 可选的用户亲自输入（SiliconFlow）

模型配置页提供 password 类型的会话密钥输入。只能由用户本人输入一枚新密钥并点击明确的提交按钮；助手不读取或代填。浏览器仅通过本机 loopback HTTP 将密钥交给本地进程，再通过 HTTPS 转发至固定的 `https://api.siliconflow.cn/v1/chat/completions`，仅允许经核验的免费模型名称，无 Pro/付费备用模型。会话密钥不写入 SQLite、文件、URL、localStorage 或 sessionStorage，不由接口回显；刷新页面清除浏览器内存。

测试通过后，用户可主动选择 AI 回测，当前会话中的密钥随明确的运行请求瞬时转发；它不进入保存的回测配置或模型审计记录。本地运行仍优先使用进程环境变量中的服务端密钥。定价可能变化，运行前需重新核实中国站价格： https://siliconflow.cn/pricing 。

## 可恢复的长窗口采集

`POST /api/collection-jobs` 接收用户完整的codes/start/end，不设10只或120天硬限制。每次`POST /api/collection-jobs/:id/step`按一个股票、最多90自然日的小区间请求公开来源；这只是单批资源/来源行数边界，不是用户研究范围限制。每批保存后才推进游标，重复版本请求不重复提交进度；中途断开可从已保存任务继续，短期在途请求需等租约后恢复。暂停停止发起下一批，已发出的当前批次会完成并保存。

合并按代码/日期去重lookback行情、按文档ID去重，冲突和失败日期区间保留警示。既不填造缺失行情也不将失败视为完整覆盖。`GET /api/collection-jobs/:id/parts?offset=0`每页20批可读取原始已保存结果。任务总量不设替代硬上限；实际部署的单行、存储、请求/响应或执行资源限制仍可能导致合并失败，界面解释并保留已完成批次，用户可分成多个数据集。显式启用后台运行的采集与新闻补充任务在页面关闭后继续；未启用后台的任务只在用户推进时运行。

## 新增宏观发布索引

新批次读取国家统计局`https://www.stats.gov.cn/sj/zxfb/`静态档案，最多3页/来源小批次，按日期过滤，保存标题、发布日期、原始链接、来源、抓取时间及SHA256，不下载或公开再分发新闻正文。它是全国宏观发布，不假装个股新闻；超出扫描范围明确标为不完整。读取robots，出现新限制或HTTP拒绝即停，不更换身份绕过。缓存24小时，来源请求间隔2秒。

生产始终使用`observed_only`：availableAt为实际首次采集时间，因此今天发现的历史索引不会进入过去的AI决策。来源显示日期不能证明历史版本/首次公开时间。适配器保留`historical_reported`研究模式供代码层实验，但产品并未启用；若以后启用，须明确披露历史版本/修订偏差。资料出处和网站条款见各记录，国家统计局条款：https://www.stats.gov.cn/wzgl/202302/t20230217_1912857.html 。

未启用人民银行（robots禁止）、发改委（访问规则受限）、外汇局（转载需要授权）、新浪静态即时标题（缺可靠历史时点）等未满足本次条件的来源。东方财富原有搜索若返回406，保留原失败提示，新增来源不代表绕过其限制或恢复其覆盖。

## 每日停复牌与可交易池

新回测按有效日期和信息可用时间计算可交易池。导入股票可以包含 `suspensionEvidence: [{start,end,status:'suspended'|'resumed',availableAt,sourceUrl}]`。`availableAt` 必须带明确时区；来源须 HTTPS，由导入者核验其真实内容。只有截止当时已知且日期覆盖的记录生效；未来停牌或未来披露不能提前剔除股票。尚未接入完整权威停复牌历史库，不会把今日状态回填到历史。

已知停牌从当日调仓池剔除，不删除历史行或已有资产。规则基线保留冻结持仓占用的权重；模型接收同一掩码和冻结权重，无法假设已卖出。执行时按次日开盘前已知状态再次检查；无日线/零成交量单独标记为不明缺口，不假称停牌。已有持仓按最近有效收盘继续估值并显示价格日期和陈旧标记；复牌后恢复交易规则检查。缺失个股不会导致其他具备规则证据的股票整轮停掉，已保存旧版回测保持其旧规则。

新增采集的东方财富和国家统计局可修订索引采用 `observed_only`：`reportedAt`/`publicationDate` 是来源声称的日期，`firstObservedAt` 是实际观察时间，`availableAt` 不能早于后者。不会将今天发现的摘要假装提供给过去的 AI。已有保存数据不改写；严格研究应重新采集或导入具备当时存档证据的数据。AI可先生成查询，由本地历史资料检索器过滤日期后返回公告/新闻元数据与来源；不调用会泄漏未来信息的普通网页搜索。

### 可选的来源标注日期实验与官方公司新闻

新回测可明确选择 `newsMode:'reported_publication'`；默认 `strict_observed`。实验模式只针对记录了来源发布日期的 observed-only 新闻，保守从发布日期次日开始可见；保存实际观察时间与模式，不宣称历史存档已验证。该模式可用于敏感性对照，但索引/网页修订仍可能引入回看偏差。相同模型对比应采用相同模式。

页面的“补充官方公司新闻链接”支持1–3条 `https://www.byd.com/cn/news/YYYY/detailNNN` 来源详情链接，使用通用解析器读取官方页面实际“发布于”字段，不从文中活动日期猜时间。示例核验链接：https://www.byd.com/cn/news/2024/detail548 。只保存标题、日期、原文链接、获取时间和SHA-256，不保存正文/图片。仅接纳当前数据集中002594及所选日期内记录，创建新副本，不修改已有回测。该工具不是全市场新闻搜索，平台增加AI主动检索本地截止日资料，不将当前互联网网页直接回填到历史决策。robots变化或拒绝访问立即停止，不绕过限制。

## 跨公司财经新闻：每日经济新闻

已接入每经公开搜索页使用的请求格式，支持关键词（公司名/代码/行业）、可选研究公司关联、日期区间和每次8条翻页。日期请求使用 `startTime/endTime: YYYY-MM-DD HH:mm:ss`，再对返回的日精度日期做防御性筛选。搜索命中只是检索关联，`code:null`，`association.requestedCompanyCode` 不被称为官方证券标签。返回条目中的每经AI快讯会标明来源生成属性，不代表本平台模型分析。

仅保留来源明确为“每日经济新闻/每经网/每经”的标题、作者、日期与原文链接。来源空白或第三方转载、全文、digest/content摘要都不保存。每条来源有查询条件、首次观察时间、响应摘要和完整性说明；不把搜索命中总数当作完整档案，日期/排序/修订仍存在限制。服务器对相同查询缓存1小时，来源拒绝访问、robots规则变化或格式变化立即停止，不绕过限制。

严格模式保持观察时间门槛；明确选择“来源标注发布日期”实验模式才按发布日期次日释放。firstPublishedAt保持null，不能把当前网页日期称为已验证首发。补入新闻创建新数据集副本；重复网址不会追加或覆写已有内容，旧回测不受影响。每页只取8条是来源批次控制，不是总研究范围硬上限。

使用范围是私人非商业研究，部署保持所有者私有。不得把采集结果、文章或摘要推到公开仓库/公开网站。来源政策：https://www.nbd.com.cn/copyright/ 与 https://www.nbd.com.cn/privacy ，来源搜索页：https://www.nbd.com.cn/search/article_search/ 。源站政策可能变化，采集可用不等于授予再分发权。

### 开源复用边界

本适配器根据经核验的公开网页请求格式独立实现，没有复制RSSHub的AGPL实现。RSSHub当前AGPL许可证与本项目分发方式需要单独评估；此处未新部署RSSHub或引入其代码。AKShare的MIT授权与新闻数据源权利是两件事，已研究的stock_news_em近期少量结果不能替代历史全量新闻库。未来可单独配置授权允许的标准RSS源，但本次不宣称已接入RSSHub服务。

### 已直接复用 RSSHub 代码的独立采集器

`connectors/rsshub-nbd/` 包含直接改编的 RSSHub NBD 路由：固定提交 `fd9cc3bf1566657292ae86427d0ce939b832f219`、逐字保留的上游文件、AGPL完整许可证、NOTICE、校验摘要及全部修改后源码。实际沿用上游Cheerio选择器、遍历和标题/链接映射，不仅仅是引用项目名称。以独立JSON文件程序交付，未把AGPL模块链接进网站Worker；进一步组合/分发须遵守对应许可，目录隔离本身不被声称为许可豁免。

运行：进入 `connectors/rsshub-nbd`，执行 `npm ci --ignore-scripts`、`npm test`，然后 `node cli.mjs --private-research --category 3 --limit 3 > news.private.json`。在网站加载行情数据集后，展开“导入开源采集器新闻元数据”并选择输出JSON。应用强制观察时间门槛，丢弃正文/raw字段，以新数据集副本保留旧回测。实际输出不可提交到公开仓库。

采集器只读最近栏目、顺序小批请求、核对robots、停止拒绝访问，过滤第三方/未知来源。若网页的多个日期字段冲突，发布日期为null；即使选择发布日期实验模式，也不会猜时间或从URL补填。实时验证两条记录均发现来源时间冲突，故只能从观察时刻起可见。此采集器不是历史全库；此前完成的站内日期搜索作为独立的补充功能保留。

## 数据平台升级（2.1.0）

- 数据审计：`GET /api/data-quality?datasetId=...&asOf=YYYY-MM-DD&newsMode=...`，逐股报告实际/预计交易日、缺失日线、规则证据、公告、新闻及截止日可见数量。未知日历、没有新闻和来源失败分别标注；不把“接口返回成功”称为完整覆盖。
- 新闻：首次行情采集自动读取每经公司查询；`POST /api/news-backfill` 接收 `{datasetId,newsPages:2,background:true}`，按公司/月份分批补充，避免半年查询只取末尾新闻。页深度可选2/5/10；每个查询保存已读页数、来源命中数、是否遍历和后续偏移。新闻只保存原创来源元数据，不抓取全文，不宣称全网历史库。
- 后台任务：`POST /api/collection-jobs` 可带 `background:true`；`POST /api/collection-jobs/:id/control` 接收 `{action:'pause'|'resume'}`。同一进程顺序处理一批，浏览器关闭不停止后台采集。暂停允许当前批次保存，不主动开始下一批。进程重启后继续未过期租约外的任务。
- AI检索：运行配置 `retrievalMode:'ai_search'`。模型先提出最多3组本地查询，平台补足未覆盖股票、过滤截止时间，再调用模型做决策。保存查询、返回资料、原文链接、股票覆盖和实际引用。每个决策最多2次模型请求，预算按两阶段保守预留，usage累计；不把缺失usage记为已知费用。`POST /api/evidence-search` 可独立检查相同的截止日检索结果。
- 严格/研究模式：严格模式仍默认，缺历史普通交易状态证据就暂停；研究模式必须带 `ruleMode:'research_assumptions',acknowledgeUnverifiedRules:true`，未经核验日期假设普通非ST规则，明确标注IPO、重上市、ST、特殊期风险。它不生成虚假的ruleEvidence。`corporateActionMode:'price_only'` 不计现金分红，也不声称含分红总收益；已核验现金账模式仍在诊断事件缺乏支付/股数证据时暂停。
- 公告文本：本机安装`pdftotext`后，`POST /api/parse-filing` 接收 `{datasetId,documentId}`，仅下载该数据集巨潮公告PDF，限制12MB/30秒下载和20秒解析，保存SHA256并创建新数据集副本。扫描件不假装解析成功，未结构化财务表格。当前提取版本严格模式使用首次观察时间；发布日期实验仍有修订偏差。
- 状态：AI配置和运行状态不再固定显示未配置，状态/导出引擎版本统一2.1.0。失败数据缓存5分钟过期，成功辅助数据24小时过期。启动支持继承环境HTTP代理。

密钥已从当前README移除；历史提交中曾公开的密钥仍需所有者撤销并换新。源码更新不能撤销已泄漏的密钥。不要将真实行情、新闻结果、PDF文本或回测导出推到公共仓库。

半年多股实测详见测试报告；六个月回测属于采用明确研究假设的价格模拟，不能替代完整企业行动、历史ST/停复牌、退市与IPO规则数据。

## 复现较长的真实 AI 测试

先在平台采集股票和半年日期窗口，在“数据覆盖与检索”检查行情缺口、按月补充新闻；遇到公告来源失败可重新采集并保留原始失败记录。数据集和回测均保存在 SQLite。配置服务端 API Key 与模型之后：

    node scripts/long-test.mjs --dataset 数据集ID --research-assumptions --reported-publication

脚本先跑同数据的等权基线，再跑真实 AI（默认每5个交易日一次，每次先规划检索，再读取截止日资料并决策）；逐次检查未来行情/文档、引用来源、资金和权重上限以及重复请求是否安全。失败停止并保存具体原因，不自动反复调用模型。输出默认在私有 `.data/long-test/`，包括检索日志和回测导出。可指定 `--out`、`--base`、`--frequency`、`--delay`。

`--research-assumptions` 明确接受历史普通非ST状态未经核验、只计算价格收益；默认严格模式不伪造规则证据。`--reported-publication` 允许来源声称的发布日期用于历史实验，存在网页修订/回看偏差；省略时按首次观察时间过滤，今天抓到的新闻不能自动成为半年前已知信息。

## 2026-10-08 真实半年长测结果

以12只真实A股、2026-04-01至2026-09-30进行125个交易日的历史模拟：1500条窗口内日线全部覆盖，763条公司公告、468条公司新闻，文档合计1276条。每家公司按6个月补充新闻，共72批次；仍是有界来源检索，不是完整互联网新闻档案。

SiliconFlow `Qwen/Qwen3-8B` 完成25次AI决策、50次成功模型请求，成功决策用量625657 tokens。24次决策引用新闻；贵州茅台一季报PDF成功提取20158字符，4次决策检索到它、3次引用。截止日资料/价格、引用存在性、资金/仓位上限、次日执行和重复版本请求检查通过。

测试发现并修复12只股票各10%导致120%仓位，以及两阶段调用共用60秒超时时限的问题。后者在第24次决策发生一次远程超时，保留原不确定请求，通过显式独立副本续跑最后两次决策，完成半年；50次和token统计不包含超时请求未返回的用量。每个请求各自90秒时限，超时仍不自动重试。页面可明确确认后创建恢复副本，保留进度、原记录及剩余预算。

本次采用普通非ST规则研究假设、价格收益和来源声称发布日期实验。历史交易状态、完整企业行动和网页不可变历史版本仍未经核验；严格模式仍会阻止缺证据的交易。AI检索/引用成功也不证明其新闻解读正确。
